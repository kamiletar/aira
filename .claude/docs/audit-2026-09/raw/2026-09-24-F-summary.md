**summary:** Два продукта владельца ложатся в одну архитектуру из трёх ролей — anchor-relay проекта, community-server-relay и client-relay — при трёх условиях, продиктованных iroh 1.2 и прецедентами (Snowflake, SimpleX, chatmail, Nostr): один бинарь `aira-relay` со встроенным iroh-relay (`Server::spawn` + собственный `AccessControl`), mailbox v2, ACME, `/healthz` и регистрацией в подписанном каталоге вместо двух systemd-юнитов из M20/M21; допуск по общесетевому подписанному токену, проверяемому каждым relay офлайн (в iroh отправитель всегда идёт на home relay получателя, поэтому `shared_token`/`allowlist` для сообщества непригодны); client-relay как «Snowflake для Aira» — только транспорт, без mailbox, self-signed + pin, эфемерная запись через брокер, отдельный процесс и ключ, по умолчанию выключен на мобильных/metered/в «строгих» странах, с экраном согласия о публикации IP. Ключевое ограничение резервирования: у iroh ровно один home relay на endpoint, при падении — бесконечный backoff и стейл pkarr-запись (открытый issue #4476), поэтому резервирование транспорта = watchdog re-home + список 2–3 `RelayRef` у контакта, а N-of-M применимо только к mailbox (N=2 у разных операторов, дедуп по `envelope_id`). Новое относительно прежних отчётов: `accept_conn_limit/burst` в iroh-relay ≤1.2.0 — no-op (план M20 п.4 опирается на несуществующий лимит); `cert_mode = "Reloading"` есть в 1.2.0 (закрывает вопрос hot-reload из relay-deploy-plan); relay «на голом IP» через LE невозможен (форк `tokio-rustls-acme` знает только `Identifier::Dns`) — только pin через `CaTlsConfig::custom_server_cert_verifier`; push-URL mailbox v2 — единственный outbound/SSRF-вектор relay (ограничение (а)); в registry уже iroh/iroh-relay 1.2.0. До беты должны попасть только форматные вещи (`RelayRef` в приглашении/контакте, `RelayHello` с классом, заглушка токена, `push_allowlist`); каталог, server-relay сообщества и client-режим — новый M24 после беты (M24a ≈2–3 нед, M24b ≈3 нед) плюс ≈3–4 недели сверх M21 на standalone-продукт (Docker/musl, `init/doctor/register`, `docs/RELAY.md`). Часть доменов (docs.iroh, tailscale, simplex.chat, letsencrypt.org, chatmail.at, delta.chat, torproject) заблокирована egress-прокси — использованы GitHub-зеркала и pkg.go.dev, остальное помечено в §9.
