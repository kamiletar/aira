# Сводка агента E (spec-remainder) — 2026-09-23, HEAD 7726b46

Полный отчёт: `../spec-remainder-audit.md`. Ниже — структурированный финальный ответ агента (как есть; нумерация милстоунов в теле отчёта приведена к §6 отчёта: M24 community relays/onion, M25 группы v2, M26 мультидевайс v2, M27 Bot API v2, M28 §6.x).

**summary:** Группы §12, мультидевайс §14 и Bot API §17A существуют в коде как криптопримитивы, IPC-запросы и экраны во всех четырёх клиентах, но ни одно не доставляет данные и не готово к бете. Групповые сообщения не шифруются Sender Keys и не имеют wire-типа — `handle_send_group_message` рассылает `PlainPayload::Text` каждому участнику (включая себя) без признака группы; внутри группы нет аутентификации отправителя (любой участник знает chain key любого и может подделать `from`); создатель кладёт в `members` свой псевдоним, а получатель ищет создателя по 1:1-ключу, control-сообщения адресуются в очередь несуществующего контакта; sender-состояния не персистятся — FS на диске отсутствует, а после рестарта повторяется пара (key, nonce). «Привязка устройства» — локальная запись без синхронизации, `sync.rs`/`DeviceGroup` вне core не используются. Bot SDK — клиент демона пользователя (не «нода со своим seed»), а после wiring не получит ни одного текста: демон эмитит сырой UTF-8, CLI ждёт `MessageMeta`, GUI пробует оба, бот — `PlainPayload`. Из §6.x к бете обязательны и сломаны disappearing messages (`expires_at` ставится только в `mark_read`, которого никто не вызывает) и блокировка (`/block` = `RemoveContact`, поле `blocked` нигде не проверяется); `/verify` и ещё шесть CLI-команд — заглушки; i18n-движок (fluent, en/ru, 33 ключа) не подключён ни к одному клиенту. Рекомендация: в бете отключить все три подсистемы честно, в M19a/M19/M21 оставить только резервы (≈4 дня), реализацию вынести в M25/M26/M27, M24 зарезервировать за community relays + onion.
