## 1. Контекст и цели

Проект создаётся с нуля как замена Tox-подобных мессенджеров. Совместимость
с существующей Tox-сетью **не требуется** — это осознанное архитектурное
решение, позволяющее избавиться от legacy-ограничений 2013 года.

### Цели

- **Memory safety** — 100% safe Rust, `unsafe` только в явно аргументированных
  местах с `// SAFETY:` комментарием
- **Post-quantum security** — устойчивость к атакам квантового компьютера,
  защита от "harvest now, decrypt later"
- **Decentralization** — нет центрального сервера, нет доверенной третьей
  стороны
- **Simplicity** — асинхронная связь: чат, файлы, голосовые заметки.
  Реального времени (звонки) нет — и не будет, обоснование ниже

### Звонки исключены навсегда — обоснование

Уточнено 2026-07-30. Раньше пункт держался на слове «Simplicity», как будто это вопрос
приоритетов. Это не так: **хороший звонок стоит именно тех свойств, ради которых Aira
существует.** Разбор по слоям:

- **Транспорт не мешает** — iroh отдаёт `send_datagram` (RFC 9221, ненадёжные неупорядоченные
  датаграммы), это как раз то, что нужно медиа. Проблема не здесь
- **Рэтчет.** `PQ_RATCHET_INTERVAL = 50`. Opus кадрами по 20 мс — 50 пакетов/с, то есть
  PQ-перевыработка ключа **каждую секунду**, каждая тащит ML-KEM-768 ciphertext (1088 байт).
  Плюс на 50 pps при потерях 2–5% копятся skipped message keys. Для медиа поэтому и существует
  SRTP с одним ключом на сессию, а не рэтчет на сообщение
- **Паддинг (§6.6).** Кадр Opus 40–60 байт добивается до блока 256 → 256 × 50 = ~100 кбит/с
  в одну сторону вместо ~20. Пятикратное раздутие, и вдвое больше через relay
- **Метаданные — главное.** У голоса узнаваемый почерк: ровные 50 пакетов/с несколько минут.
  Паддинг скрывает размер, но не тайминг. Relay видит «эти два псевдонима говорили 12 минут» —
  ровно то, что Aira обещает скрыть. Плюс атаки на VBR восстанавливают фразы из шифрованного
  VoIP, значит нужен CBR, а это минус к качеству
- **Задержка.** Через relay клиент→relay→клиент; выше ~150 мс в одну сторону разговор ломается.
  В браузерной сборке (§15.5) relay обязателен всегда — там звонки плохи структурно
- **Обработка звука.** Ценность WebRTC не в транспорте, а в вылизанных AEC/шумодаве/AGC.
  В Rust это означало бы биндинги к `webrtc-audio-processing` (C++) — и «нулевой unsafe»
  получает крупную сноску
- **Нет iOS (§15.4), а входящий звонок на Android требует wake-up** через UnifiedPush/FCM,
  то есть сигнал пойдёт через инфраструктуру Google. Для фичи, которой мгновенность нужна
  больше всего, это подрывает и децентрализацию, и метаданные

Чтобы получить приемлемое качество, пришлось бы: прямой UDP (ломает браузер), один ключ на
сессию вместо рэтчета (ослабляет PQ), CBR без тяжёлого паддинга (ослабляет метаданные),
push-канал для звонка (ломает децентрализацию). Это архитектурно другой продукт.

**Что закрывает потребность вместо звонков:** голосовые заметки (§6.11, Milestone 15) — запись
Opus, отправка как медиа по существующему стеку. Все гарантии держатся: рэтчет идёт в своём
темпе, тайминг-почерка нет (всплеск, а не поток), эхоподавление не нужно — дуплекса нет.

### Не входит в scope v0.1

- ~~Голосовые/видеозвонки~~ — **исключены из проекта навсегда** (обоснование выше).
  Голосовые *заметки* — другое дело, они в scope (§6.11)
- Групповые чаты (v0.2, см. п. 12)
- Мультидевайс (v0.3, см. п. 14)
- GUI (CLI-first, egui потом, см. п. 15)
- ~~iOS~~ — **исключён из проекта** (iOS убивает фоновые P2P соединения
  через ~30 сек, VPN Extension ограничен 25MB RAM, Briar отказался от iOS
  по тем же причинам; 10% потерь push-уведомлений на SimpleX Chat)

## 3. Архитектура по слоям

```
┌─────────────────────────────────────────────────┐
│  CLI / Future GUI                               │  aira-cli
├─────────────────────────────────────────────────┤
│  Application Layer                              │
│  • Contacts (add/remove/block)                  │  aira-core
│  • Message history                              │
│  • File transfer API                            │
├─────────────────────────────────────────────────┤
│  Messaging Layer                                │
│  • Triple Ratchet / SPQR (PQ forward secrecy)   │  aira-core
│  • Message framing, ordering & padding          │
│  • File chunking & reassembly                   │
├─────────────────────────────────────────────────┤
│  Session Layer                                  │
│  • PQ Handshake (PQXDH)                        │  aira-core
│  • Hybrid KEM: X25519 + ML-KEM-768             │
│  • Identity: ML-DSA-65                          │
├─────────────────────────────────────────────────┤
│  Transport Layer                                │
│  • iroh 0.97+ (QUIC/noq + NAT traversal)       │  aira-net
│  • Peer discovery (iroh + DHT)                  │
│  • Relay store-and-forward (pairwise mailboxes) │
├─────────────────────────────────────────────────┤
│  Obfuscation Layer (pluggable, п. 11A)          │  aira-net
│  • direct / obfs4 / mimicry / REALITY / Tor     │
└─────────────────────────────────────────────────┘
```
