# Политика безопасности

## Поддерживаемые версии

| Версия | Статус |
|---|---|
| `0.3.x` | pre-release, сеть не подключена — исправления безопасности только в `main` |
| `0.5.0-beta.N` | публичная бета (план) — исправления в течение 30 дней |
| `1.0` | после внешнего аудита |

## Как сообщить об уязвимости

1. **Не открывайте публичный issue.**
2. Используйте GitHub **Security → Report a vulnerability** (private vulnerability reporting) в репозитории
   `kamiletar/aira`. Если функция недоступна — напишите владельцу репозитория через GitHub и попросите
   безопасный канал.
3. Укажите: версию/коммит, шаги воспроизведения, затронутый компонент (`aira-core`, `aira-net`, `aira-storage`,
   `aira-daemon`, клиенты, `aira-relay`), оценку последствий.

Мы подтверждаем получение в течение 7 дней, публичное раскрытие — по согласованию, не позднее 90 дней
после подтверждения (раньше, если исправление выпущено).

## Что считается уязвимостью (в приоритете)

- Нарушение Key Isolation (`docs/KEY_CONTEXTS.md`): один ключ в двух контекстах.
- Раскрытие содержимого сообщений, ключей или seed-фразы третьей стороне (включая relay).
- Раскрытие IP пользователя вопреки настройке `hide_ip` (после M19).
- Обход инвариантов форвардинга AP-1…AP-7 (`spec/03-network.md` §5.5): превращение relay/хопа в прокси в интернет,
  соединение по адресу из пакета, нетарифицированный форвардинг, хранение без регистрации.
- Паника/DoS демона или relay на внешних данных (парсеры, лимиты размеров).
- Timing-каналы в сравнениях MAC/тегов/токенов.

## Вне scope

- Атаки, требующие физического доступа к разблокированному устройству.
- Корреляция трафика глобальным наблюдателем в профилях `fast`/`standard` (см. `docs/THREAT_MODEL.md`).
- Уязвимости в зависимостях без пути эксплуатации в Aira (сообщайте upstream; `cargo audit` в CI).

## Подпись релизов

Планируется (трек M22-infra): `SHA256SUMS`, GitHub artifact attestations, подпись minisign, SignPath для Windows.
До этого проверяйте `.sha256`-файлы из релиза.
