# Модель угроз Aira

> Версия документа: сентябрь 2026 (по аудиту `.claude/docs/release-audit-2026-09.md`). Нормативная спека — `spec/13-threat-model.md` (§11).
> Колонка «Статус»: **код** — работает в 0.3.5; **M<N>** — запланировано в милстоуне; **нет** — не обещаем.

Aira не называет себя «анонимным» или «невзламываемым» мессенджером. Ниже — что именно обещано какому наблюдателю
и с какой версии.

## 1. Обещания по наблюдателям

| Наблюдатель | Что видит в 0.3.5 | После M19/M20 (бета 0.5) | После M24b (Aira Onion) | После M24d (mix-профиль) |
|---|---|---|---|---|
| **Собеседник** (контакт) | ваш IP при любом прямом соединении (сети в демоне ещё нет) | **IP скрыт**: трафик только через relay, прямое соединение — по вашему разрешению на контакт | то же, плюс не видит ваш relay/guard | то же |
| **Оператор одного relay / хопа / mailbox** | — | IP + EndpointId + набор коробок (один relay видит всё, кроме содержимого) | либо ваш IP (guard), либо mailbox, никогда связку; корреляция по времени требует сговора guard + mailbox | сговор не даёт корреляции без долгих наблюдений |
| **Провайдер / DPI** | QUIC v1 к relay/пирам с читаемым ALPN | то же; relay на своём домене по WSS:443 | вход через резидентные мосты без каталога; с M24c — обфусцированные датаграммы | то же |
| **Глобальный пассивный наблюдатель** | всё | всё (тайминг, объёмы) | корреляция по времени возможна, как в Tor | Poisson-микширование + cover-трафик; анонимность ограничена числом активных mix-клиентов |
| **Sybil-оператор многих хопов** | — | — | guard-персистентность, разнообразие /16 и AS, вес по uptime | то же |

Содержимое сообщений не видит никто из перечисленных ни в одной версии (после подключения сети — протокол v2, M19a).

## 2. Таблица угроз

| Угроза | Митигация | Статус |
|---|---|---|
| Пассивное прослушивание сейчас | QUIC TLS 1.3 (iroh) + ChaCha20-Poly1305 поверх | код (транспорт), M19 (подключение) |
| «Собрать сейчас, расшифровать потом» (квантовый противник) | гибридный KEM X25519 + ML-KEM-768 в handshake и ratchet; per-file ключ для файлов ≥ 1 MB | ядро: код; PQ-шаг ratchet и файлы — M19a |
| Подделка идентичности | ML-DSA-65, per-contact псевдонимы, TOFU + Safety Number | код (ядро); `/verify` в клиентах — M19b |
| Компрометация одного сообщения / устройства | Triple Ratchet: forward secrecy, PQ-шаг каждые ~50 сообщений | M19a (транзакционный decrypt, активный PQ-шаг) |
| Metadata «кто с кем» | pairwise mailbox v2 (две коробки на пару), паддинг 256–4096 B, relay-only | M21 / код (паддинг) |
| Раскрытие IP собеседнику | `hide_ip = true`: endpoint без IP-транспортов, ссылка-приглашение без IP | M19/M19b |
| Раскрытие IP оператору relay | Aira Onion: маршрут S→guard→middle→mailbox←middle←guard←R | M24b |
| Корреляция по времени (сговор guard + mailbox, глобальный наблюдатель) | mix-профиль (Loopix): задержки + cover-петли | M24d; в `fast`/`standard` — **не обещаем** |
| Блокировка по списку relay (РКН/GFW) | нет глобального каталога: мосты через контакты и invitation link, hidden mode для strict-стран | M24a/M24c |
| DPI-сигнатура транспорта | обфускация датаграмм первого хопа (`CustomTransport`); relay по WSS:443 | M24c / M20 |
| Паразитный прокси через relay/хопы (чужой трафик, exit в интернет, хранилище) | инварианты AP-1…AP-7: нет exit, следующий хоп только из своей таблицы, фиксированные ячейки, тарифицированные байты, хранилище по регистрации | M21 (mailbox), M24b (хопы) |
| Спам / массовые Contact Request | contact-first, адаптивный PoW (16→28 бит, nonce + slot), `ContactStamp`, rate limit | M22 |
| DDoS / исчерпание соединений | QUIC anti-amplification (iroh), лимиты стримов/окон, таймауты, tiers, `EndpointHooks` | M19 / M22 |
| Флуд relay | квоты mailbox v2 (100 конвертов / 10 MB / TTL 7 дней / total cap), регистрация ≤ 20/сутки, intro PoW, `client.rx` iroh-relay | M21 |
| Sybil / eclipse | разнообразие /16 и AS, proof-by-use в peer exchange, guard'ы | M24b |
| Доказательство авторства третьей стороне | deniability: симметричные MAC, без подписи сообщений | код (ядро) |
| Link preview раскрывает IP | превью генерирует отправитель; в hide_ip-профиле — opt-in | M19b |
| Утечка через логи | IP собеседников и EndpointId не выше `debug`; relay — `RUST_LOG=warn` | M19 / M20 |
| Memory safety | safe Rust, `#![deny(unsafe_code)]` в core/storage/onion, zeroize | код |

## 3. Что не в scope

- Компрометация конечного устройства (скриншоты, malware, физический доступ к разблокированному устройству).
- Анонимность против глобального наблюдателя в профилях `fast` и `standard`.
- Скрытие самого факта использования Aira от провайдера без мостов (M24c) — «устойчивость, не невидимость».
- Файлы > 10 MB в скрытых профилях идут только прямым соединением с явным предупреждением (M24b).

## 4. Известные ограничения текущего кода (0.3.5)

По аудиту: сеть не подключена к демону; ratchet-протокол v1 будет заменён v2 без совместимости; DPI-транспорты
`transport/*` удаляются как несостоятельные; группы, мультидевайс и Bot API отключаются в бете; APK не подписан.
Полный список — `.claude/docs/release-audit-2026-09.md` §0 и §8.
